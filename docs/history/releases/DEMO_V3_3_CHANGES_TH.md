# ERP DEMO v3.3.0 — รายการปรับปรุง Forecast และ Business Analytics

วันที่ 6 กันยายน 2569 · รุ่นแพ็กเกจ 1.3.2 · พัฒนาต่อจาก DEMO v3.2.1

รอบนี้นำข้อเสนอจากการศึกษา ERP / Business Analyst / Quant มาปรับใช้กับโค้ดจริง โดยเน้นความถูกต้องของข้อมูลเวลา ความยุติธรรมในการเปรียบเทียบโมเดล และการแสดงผลที่ไม่สร้างความมั่นใจเกินหลักฐาน ระบบยังเป็น Local DEMO เก็บข้อมูลในเบราว์เซอร์ ชุดนี้ยังไม่ได้เผยแพร่ขึ้น GitHub Pages หรือ Vercel ให้ผู้ใช้

## สิ่งที่แก้แล้ว

| MASE ใช้ข้อมูลช่วงทดสอบมาช่วยคำนวณตัวหาร | คำนวณสเกล naive จากข้อมูลฝึกของแต่ละรอบ แล้วเฉลี่ย scaled absolute error | ข้อมูลเดือนที่กำลังทดสอบไม่รั่วเข้าสเกลของรอบนั้น |
| ตัวหาร WAPE/MASE เป็นศูนย์แต่บางหน้าตีความว่าแม่นยำ | เก็บสถานะคำนวณไม่ได้และแสดง — ไม่ให้สถานะ Healthy จาก WAPE ที่คำนวณไม่ได้ | ประวัติยอดศูนย์ทั้งหมดไม่ถูกตีความว่ามีหลักฐานยืนยันความแม่นยำ |
| sMAPE ตัดรอบ actual=prediction=0 ออกจากจำนวนรอบ | ให้นับรอบนั้นเป็น error 0 และรวมในจำนวนรอบ | นิยามค่าเฉลี่ยสม่ำเสมอเมื่อยอดขายบางเดือนเป็นศูนย์ |
| แสดงคะแนนความน่าเชื่อถือเป็น % จากสูตร heuristic | เอาคะแนนนี้ออก แสดงจำนวนเดือนทดสอบและข้อความว่ายังไม่ได้ยืนยันกับข้อมูลใหม่ | ไม่มีเปอร์เซ็นต์ที่ชวนเข้าใจว่าเป็นโอกาสพยากรณ์ถูก |
| ใช้ 1.28 × RMSE × √h กับทุกโมเดลและทุกระยะ | ยกเลิกสูตรดังกล่าว แสดงสถานการณ์ต่ำ/สูงเฉพาะระยะ 1 เดือน เมื่อมี residual อย่างน้อย 8 รอบ | ระยะไกลหรือข้อมูลไม่พอแสดง — ไม่สร้างช่วงแคบเป็นศูนย์เอง |
| เรียกค่าพยากรณ์จุดว่า P50 | เปลี่ยนหัวตารางเป็น Base Forecast และสถานการณ์ต่ำ/สูง | ไม่อ้างว่าค่าจุดจากทุกโมเดลเป็นมัธยฐาน |
| Analytics อ้างอิงเดือนล่าสุดที่ยอดบวก | ใช้เดือนปฏิทินล่าสุดที่เกี่ยวข้องและไม่เลือกเดือนอนาคตในมุมมองทั้งปี | รวมเดือนที่ยอดศูนย์ และเริ่มอนาคตจากเดือนอ้างอิงจริง |
| มกราคมของปีปัจจุบันไม่ถอยไปธันวาคมปีก่อน | แก้การคำนวณเดือนอ้างอิงข้ามปี | ประวัติอัตโนมัติในเดือนมกราคมสิ้นสุดธันวาคมปีก่อน |
| Quant ตัดเดือนยอดศูนย์ออก | เก็บเดือนศูนย์ใน regime, drawdown และ anomaly เมื่อประวัติครบ | การหดตัวจนถึงศูนย์ไม่หายไปจากการวิเคราะห์ |
| Monte Carlo ใช้ความผันผวนยอดขายแทน error เมื่อไม่มี CV | งดจำลองเมื่อไม่มี CV RMSE หรืออินพุตไม่ถูกต้อง | โอกาสถึงเป้าและ tail risk แสดง —; ตารางไม่สรุปว่าโอกาสต่ำจากข้อมูลที่หาย |
| Composite risk ใช้ค่าแทน 0 เมื่อ forecast metric ไม่พร้อม | งดคะแนนรวมเมื่อองค์ประกอบที่รับเข้าไม่เป็นค่าจำกัด | ไม่ได้คะแนนความเสี่ยงต่ำเพราะ WAPE หาย |
| Pipeline approval proxy อาจถูกเข้าใจว่าอัตราชนะงาน | ระบุว่าเป็นอัตราอนุมัติเอกสาร และเปิดเผยสมมติฐาน DEMO 35% เมื่อประวัติน้อยกว่า 5 ใบ | อ่านแยกจากยอดขายคาดการณ์และผลชนะ/แพ้งานจริง |

## วิธีอ่านช่วงสถานการณ์ใหม่

- ใช้ residual = ยอดจริง − ค่าพยากรณ์ ของการทดสอบย้อนหลังแบบหนึ่งเดือน
- สถานการณ์ต่ำ = Base + เปอร์เซ็นไทล์ 10 ของ residual; สูง = Base + เปอร์เซ็นไทล์ 90; จำกัดยอดไม่ให้ติดลบ
- แสดงได้เมื่อมี residual อย่างน้อย 8 รอบ เกณฑ์นี้เป็นนโยบายขั้นต่ำของ DEMO ไม่ใช่หลักประกันทางสถิติ
- เป็นสถานการณ์เชิงพรรณนาจากข้อผิดพลาดชุดเดิม ยังไม่ใช่ prediction interval ที่ยืนยัน coverage 80% แล้ว
- ชุดเดียวกันยังถูกใช้เลือกโมเดลด้วย จึงต้องทดสอบกับข้อมูลใหม่แยกต่างหากก่อนนำไปวางแผนจริง
- ระยะ 2 เดือนขึ้นไปยังไม่มีการประเมิน error เฉพาะ horizon จึงไม่แสดงช่วงต่ำ/สูง แต่ยังแสดงค่าพยากรณ์จุดเมื่อข้อมูลพร้อม
- Monte Carlo เป็นอีกการจำลองหนึ่ง สมมติ error แบบ Normal อิสระและตัดยอดติดลบเป็น 0 ตัวเลขความน่าจะเป็นขึ้นกับสมมติฐานนี้ ไม่ใช่อัตราความสำเร็จที่พิสูจน์แล้ว

## ความครบถ้วนข้อมูลและการทดลอง DEMO

1. ใช้ข้อมูลสมมติและสำรอง Backup JSON ก่อนอัปเดต
2. เลือกสาขา ปี และเดือนให้ตรงกับข้อมูลที่มีจริง หากเลือกทุกสาขา ต้องมีชุดข้อมูลของทุกสาขาในเดือนที่จะใช้
3. ชุดข้อมูลรายเดือนที่บันทึกไว้และมีรายการว่างถูกอ่านเป็นยอดที่บันทึก 0 แต่ไม่ได้พิสูจน์ว่าพนักงานลงข้อมูลครบแล้ว
4. ไม่มีชุดข้อมูลรายเดือน ข้อมูล JSON เสีย หรือโครงสร้างหลักไม่ครบ หมายถึงยังไม่ทราบยอดเดือนนั้น การพบช่องว่างหลังเริ่มประวัติจะระงับพยากรณ์ทั้งชุด
5. ยังไม่มีหน้าจอยืนยันปิดเดือนที่ไม่มีธุรกรรมโดยเฉพาะ หากข้อมูลขาด ให้ตรวจและนำเข้าชุดข้อมูลเดือนที่ครบจริงก่อน ไม่สร้างเอกสารขายปลอมเพื่อให้พยากรณ์ทำงาน
6. ประวัติ 1–3 เดือนอาจแสดงยอดล่าสุดเป็นฐานชั่วคราว แต่จะไม่อ้างว่าผ่านการเปรียบเทียบโมเดลแล้ว
7. Holt-Winters ต้องมีข้อมูล 24 เดือนสำหรับฝึก และอย่างน้อย 27 เดือนเพื่อเข้าตารางเปรียบเทียบที่มี 3 รอบทดสอบ
8. การเผยแพร่โค้ดใหม่ที่ URL เดิมไม่ใช่การส่งข้อมูลผู้ใช้คนหนึ่งไปให้ผู้ใช้อีกคน ข้อมูล Local DEMO ยังแยกตามเครื่อง/เบราว์เซอร์/origin

## ข้อจำกัดและงานถัดไป

- ยังเป็น DEMO ไม่ใช่ ERP พร้อมใช้งานจริงหลายคน ไม่มี backend authentication/authorization/ฐานข้อมูลกลางในรอบนี้
- ยังไม่ได้ทำ UI redesign ทั้งระบบ หรือแก้ทุกประเด็นในรายงานศึกษาในครั้งเดียว
- ความครบถ้วนของชุดข้อมูลไม่ได้เท่ากับความถูกต้องทางธุรกิจ ต้องมีผู้รับผิดชอบตรวจเดือนและแหล่งรายการ
- ยังไม่มี final holdout, horizon-specific backtest, การวัด interval coverage, seasonal-naive benchmark หรือการทดสอบหลายธุรกิจแยกกัน
- HHI thresholds และ composite weights ยังคงเป็น heuristic เดิม ไม่ใช่มาตรฐานตัดสินความเสี่ยงของทุกบริษัท; บาง KPI เชิงพรรณนานอก forecast ยังต้องปรับการแยก “ไม่มีฐานข้อมูล” เพิ่มเติม
- Modified Z-score เมื่อ MAD=0 ยังไม่มีวิธี fallback การไม่พบสัญญาณจึงไม่ได้ยืนยันว่าไม่มีความผิดปกติ
- Quote approval ยังไม่ใช่ผล won/lost ต้องออกแบบสถานะผลการขายและวันปิดดีลก่อนสร้าง conversion model
- ควรทำ KPI dictionary พร้อม drill-down ไปเอกสารต้นทาง, requirement traceability และ UAT กับงานจริงต่อจากรอบนี้
- ควรลด bundle และค่อยแยก CSS/โมดูลด้วย visual regression test หลังได้ URL และภาพของเว็บไซต์จริง
