# ERP DEMO 3.3.0 FLAT — ชุดอัปโหลดไฟล์ระดับเดียวกัน

ชุดนี้แก้ปัญหาการอัปโหลดที่ทำให้ไฟล์ใน assets ไปอยู่ระดับเดียวกับ index.html โดย build ใหม่ให้หน้าเว็บเรียก JavaScript, CSS, โลโก้ และ CSS หน้าพิมพ์จากระดับเดียวกันทั้งหมด ระบบธุรกิจยังเป็น DEMO 3.3.0 และใช้ข้อมูลในเบราว์เซอร์เดิม

## วิธีอัปโหลดสำหรับ WedsiteDemo

1. แตก ERP_DEMO_3_3_0_FLAT_UPLOAD.zip ลงในโฟลเดอร์ใหม่
2. เปิด repository https://github.com/20pattaratron-creator/WedsiteDemo ที่ branch main
3. เลือก Add file → Upload files
4. เลือกไฟล์ข้างในโฟลเดอร์ที่แตก ZIP ทั้งหมด แล้วอัปโหลดไว้ระดับเดียวกัน ไม่มีโฟลเดอร์ assets ในชุดนี้
5. ต้องแทนที่ index.html และ deployment-check.html เดิม ชื่อไฟล์ต้องตรง ไม่เป็น index (1).html หรือ deployment-check (1).html
6. กด Commit changes แล้วรอการเผยแพร่ GitHub Pages เสร็จ
7. เปิด https://20pattaratron-creator.github.io/WedsiteDemo/deployment-check.html แล้วกดตรวจอีกครั้ง
8. หัวหน้าตรวจต้องแสดง “ERP DEMO 3.3.0 FLAT” และผลต้องผ่านครบ 7 ไฟล์
9. เปิด https://20pattaratron-creator.github.io/WedsiteDemo/ แล้วกด Ctrl + Shift + R

ไฟล์ .nojekyll อาจถูกซ่อนในเครื่อง ให้รวมไปด้วยหากเลือกได้ ชุดเว็บนี้ไม่มีไฟล์ runtime ที่ต้องขึ้นต้นด้วยขีดล่าง

## การแปลผลตรวจ

- ยังเห็นหัว “3.3.0” ไม่มี FLAT: เว็บไซต์ยังแสดงหน้าตรวจชุดเก่า ตรวจชื่อไฟล์ที่แทนที่และรอเผยแพร่
- ยังพบพาธ assets/: หน้าเว็บหรือหน้าตรวจยังเป็นชุดเก่า ไม่ใช่ชุด FLAT
- พบ 404 ของชื่อไฟล์ที่ไม่มี assets/: ไฟล์นั้นยังอัปโหลดไม่ครบ หรืออยู่คนละตำแหน่งกับ index.html
- พบ “ไฟล์ไม่ตรงรุ่น”: แทนที่ไฟล์จาก ZIP ชุด FLAT เดียวกันทั้งหมด
- ผ่านครบ 7 ไฟล์: ไฟล์หลักตรงกับชุดนี้ จากนั้นจึงตรวจการใช้งานเมนูและการพิมพ์เพิ่มเติม

## รายการแก้ไข

- เพิ่มคำสั่ง npm run build:flat ให้ Vite ส่งไฟล์ runtime ทุกไฟล์ไว้ที่ dist-flat/ ระดับเดียวกัน
- กำหนด base แบบ relative เพื่อให้ใช้ใต้ /WedsiteDemo/ ได้
- ให้ Vite ปรับพาธ HTML, รูปภาพและ import.meta.url ที่หน้าพิมพ์ใช้พร้อมกัน
- เพิ่มป้ายรุ่น FLAT และข้อความช่วยเหลือที่ตรงกับรูปแบบอัปโหลดนี้
- ปรับตัวสร้าง deployment-check.html ให้ตรวจได้ทั้งชุด assets แบบเดิมและชุด FLAT พร้อมตรวจ SHA-256/MIME
- ขยายชุดทดสอบ deployment ให้ตรวจชุด FLAT และตรวจ checksum ของทั้ง 7 ไฟล์ด้วย

## ผลตรวจ

ชุด FLAT ผ่าน 6 กรณีใน Node.js/jsdom/VM Modules: เริ่ม compiled bundle ใต้ repository prefix และบันทึกใบเสนอราคาได้; หน้าพิมพ์ทั้ง 3 แบบอ้าง CSS ที่มีอยู่; แจ้งไฟล์ขาดได้โดยไม่พึ่ง bundle; boot ล้มเหลวไม่อ้างว่าพร้อม; guard บันทึกไม่บล็อกตัวเอง; manifest ตรงกับทุกไฟล์และไม่มี assets/ ในพาธภายใน HTML ของชุด FLAT

ชุด deployment แบบเดิมผ่าน 6 กรณีเช่นกัน รอบนี้ไม่ได้เปลี่ยนสูตรหรือกฎธุรกิจ จึงไม่ได้รันทดสอบธุรกิจ 64 กรณีซ้ำ ผล 64 กรณีจากรุ่นก่อนยังเก็บไว้ใน test-results.txt

ยังไม่ได้เผยแพร่ไฟล์ชุด FLAT ไปยังบัญชี GitHub ของผู้ใช้ และผลทดสอบจำลองนี้ไม่ใช่การตรวจภาพในเบราว์เซอร์จริงหรือการยืนยันว่าเว็บไซต์ live อัปเดตแล้ว

## สำหรับผู้พัฒนา

npm ci
npm run build:flat
npm run test:deployment:flat

ผลเว็บอยู่ใน dist-flat/ ส่วน npm run build ยังคงสร้างชุด assets แบบเดิมใน dist/
